## 3. 面試官最可能追問的技術問題

### Q1. 為什麼用 BM25，不用向量資料庫？
- **資料量小、結構明確**：7 份規章、81 條條文，每條都有明確的辦法名稱和條號；規章用語固定，關鍵字檢索就夠準
- **可解釋、可除錯**：BM25 分數和命中詞看得到。例如「學生餐廳營業時間」只命中「學生」「時間」也拿到 4.94 分，我能看出原因並加上**覆蓋率門檻**（條文至少要含一半查詢詞）擋掉；向量檢索的相似度很難這樣調
- **「查不到」要能明確判斷**：這個系統的核心是查不到就分流，不要硬答。向量檢索一定會回傳「最相近」的結果，比較難劃出「無關」的界線
- **實作細節**：排序用字元 bigram（不怕斷詞錯）；覆蓋率用 jieba 繁體詞典斷詞（避免「費會」「會退」這種跨詞雜訊），再加口語→規章用語的同義詞表（大二→第二學年、當兵→服役）。這個調整讓口語題命中率從 17% 提升到 83%
- **什麼時候會換**：文件量到幾百份以上、或口語和規章用語落差大（例如「電腦課」vs「電腦及語言教室課程」）時，會改成 **BM25 + 向量的混合檢索**，保留 BM25 的門檻機制當作「查無」判斷

### Q2. MCP 和直接呼叫 API 有什麼不同？
- **直接呼叫 API**：我自己寫 agent loop——組 prompt、定義 tools、解析 tool call、執行、再回填。工具和某一個 LLM 平台綁在一起
- **MCP**：把「工具」包成標準協定的 server，**任何支援 MCP 的 Host**（Claude Desktop、Claude Code、IDE、其他 Agent 平台）都能直接接，不用改工具程式碼。Host 負責對話和決定何時呼叫工具，server 只負責確定性的功能
- **在這個專案的好處**：
  - 不需要 API key，用 Claude Desktop 就能 demo；學校之後換平台，工具可以沿用
  - docstring 就是工具描述，「什麼時候該用／不該用」寫在 docstring 裡，引導 LLM 選對工具
  - 職責分離：**LLM 只負責理解和措辭，事實（條文）、計算（學分比大小）、紀錄（分流單）交給確定性的工具**
- **代價**：多一層程序間通訊（stdio）；stdout 不能有任何 print，否則 JSON-RPC 會壞（這是我踩過的坑，所以全部用 logging 寫 stderr）

### Q3. 如果要接到 OpenClaw（或其他 Agent 平台）要改哪些地方？
- **工具本身幾乎不用改**：`core/` 是純函式，`server.py` 是標準 MCP server
- **要改的地方**：
  1. **連線設定**：在平台的 MCP 設定加入這個 server（command + args），跟 Claude Desktop 的 config 一樣
  2. **傳輸方式**：若平台在雲端、不能啟動本機程序，要把 `mcp.run()` 改成 `mcp.run(transport="streamable-http")`，並加上 **驗證**（API token / SSO）和 HTTPS
  3. **System prompt**：`campus_assistant` 目前是 MCP prompt，有些平台不會自動載入，要把內容貼到平台的 agent 指令裡
  4. **部署**：從個人電腦搬到學校主機或容器；`logs.db` 改用學校的資料庫（多人同時寫入時 SQLite 不適合）
  5. **身分**：目前不知道是誰在問，接到正式平台要串學校 SSO，才能做「查自己的學籍」這類個人化功能（並且權限要在工具層檢查，不能靠 LLM）
- **要驗證的**：換了 LLM 之後，重新跑 `eval/run_eval.py` 和實際對話測試，確認新的模型也會乖乖呼叫工具、附出處

### Q4. 個資怎麼保護？還有哪些不足？
- **目前做的**：
  - `mask_pii` 用 regex 遮蔽 Email、身分證、手機、學號；**寫進 log 和分流單之前一定先遮蔽**（`log_interaction`、`route_case` 內部自己呼叫，不依賴 LLM 記得）
  - 身分證要通過**檢查碼**才算，避免和同格式的學號混淆
  - 「16 學分」「110 學年度」不會被誤遮
  - 檢索前也先遮蔽，並移除遮蔽標記，避免影響查詢
  - `logs.db` 不進版控；測試用暫存 DB，不碰正式資料
- **不足**：
  - **使用者的原始問題會送到 LLM 供應商**——遮蔽只發生在我的工具裡，Claude 本身看得到原文。正式導入要評估：資料處理協議、選擇不拿資料訓練的方案，或在前端先遮蔽
  - regex 抓不到**姓名、地址、生日**、病史等敏感資訊
  - 學號格式是**假設的**（A/B/N + 9 碼），要跟校方確認
  - `logs.db` 沒加密、沒有存取控制、沒有保存期限和刪除機制
  - 沒有身分驗證，無法限制誰能看分流單
- **改進方向**：前端先遮蔽、加入 NER 模型抓姓名、log 設保存期限（例如 180 天）、依個資法建立存取紀錄

### Q5. 怎麼知道 AI 答對了？
- **分層驗證**：
  1. **單元測試**（141 個）：檢索、個資遮蔽、學分規則、分流各自測。例如「學分上限是 22 不是 25」、「規則的門檻數字一定要出現在出處條文裡」、34 條規則逐條的邊界值（門檻、門檻 ±1）、分流關鍵字對到正確窗口
  2. **評估集**（`eval/questions.yaml`，20 題）：12 題可回答、4 題要計算、4 題應分流，分別算命中率、計算正確率、分流正確率，**有目標值**（80% / 100% / 75%）
  3. **上線後**：`log_interaction` 記每次問答是否有回答、引用哪些出處 → 算自動解答率、分流率；答不出來的問題做補洞報告
- **設計上降低答錯的機會**：
  - 每個回答**必須附出處**，學生和承辦人都能回頭核對原文
  - 數字比較交給 `check_credit_rule`，避免 LLM 算錯「16 > 22」
  - 規則有 `verified` 欄位，未經核對的規則會回傳 warning；34 條規則都對照 PDF 原文核對過（`docs/規則核對表.md`），有測試確保不會有未核對的規則混進來
  - 查不到就分流，不讓 LLM 自己編
- **誠實說限制**：eval 目前測的是「檢索有沒有找到正確條文」，還沒測「LLM 最後的回答措辭是否正確」。下一步是做 **LLM-as-judge** 或請承辦人抽樣人工評分

### Q6. 如果規章改版怎麼辦？
- **流程**：把新版 PDF 放進 `kb/` → 執行 `python scripts/ingest.py` 重新切條文 → 重跑 `pytest` 和 `eval/run_eval.py` → 沒退步才上線
- **防呆**：
  - ingest 會印出去重和警告，條文數量異常可以發現
  - 測試 `test_threshold_appears_in_source_article` 會檢查 `rules.yaml` 的門檻數字還在出處條文裡——如果改版把 22 學分改成 24 學分，**測試會失敗**，提醒要更新規則
  - `rules.yaml` 改了要人工核對後才能設 `verified: true`
- **還可以加強**：
  - 在 chunks 裡記錄**版本／生效日期**，回答時附上「依 2026 年 X 月修正版」
  - 新舊版 diff 報告，讓承辦人只審變動的條文
  - 學期交界時新舊規定並存（例如「110 學年度以前入學適用舊制」）目前沒有處理

## 4. 兩分鐘 Demo 口述稿

> 括號內是動作，約 2 分鐘。

**【問題】（20 秒）**
「各位好。很多學校導入 AI 客服後遇到兩個問題：一是**答不出來**，只會說『查無此題』，學生不知道下一步；二是**答錯**，像是 LLM 把學分上限說錯、或編出規章沒有的內容。對學校來說，答錯比答不出來更嚴重。」

**【設計原則】（25 秒）**
「所以我的設計原則是：**LLM 只負責理解和措辭，事實、計算、權限交給確定性的工具**。我用 MCP 做了一個校務助理的工具 server，接在 Claude Desktop 上。三個重點：第一，每個回答都要附規章出處；第二，學分這類數字判斷用程式算；第三，查不到不說查無此題，而是開分流單，告訴學生找哪個單位。個資在寫進紀錄前會先遮蔽。」

**【實際操作】（50 秒）**
（問題 1）「我想停修一門課，停修後學費會退嗎？」
→「它先查規章，回答不退費，並附上**選課辦法第七條**。」

（問題 2）「我大二，這學期只選了 14 學分，這樣可以嗎？」
→「這裡它不自己比大小，而是呼叫 `check_credit_rule`，程式判斷低於 16 學分下限，出處是**選課辦法第三條**。」

（問題 3）「學生宿舍什麼時候可以申請？」
→「知識庫沒有宿舍規定，所以它**不會亂答**，而是開分流單，直接對到**學務處宿管中心、分機 82076**，給學生單號，請學生帶著單號去聯絡。」

（問題 4）「我的學號是 A110123456，手機 0912-345-678，想問停修」
→「學號和手機在寫進紀錄前已經被遮蔽成 `[STUDENT_ID]`、`[PHONE]`。」（可打開 logs.db 給看）

**【成效數字】（15 秒）**
「我建了 20 題評估集：可回答的題目命中 83%、學分計算 100% 正確、應分流的 75% 正確分流，另外有 141 個自動化測試。答錯的題目我也都知道原因，例如口語『電腦課』和條文『電腦及語言教室課程』用語不同。」

**【下一步】（10 秒）**
